## 0. 五条核心判断

1. **【事实】**国内头部厂商已完成卡位，形态趋同：**IM/工作台内对话助理 + 智能体编排台 + 把企业 OpenAPI 转成工具**。金蝶苍穹做"OpenAPI 契约→MCP 工具"自动转换，用友称接入 4000 个企业应用 API——这是"对话即操作"的真实工程路径，不是 RPA 点界面。
2. **【推断】**成熟度集中在 **L2（单步写 + 预览确认）**，少数到 **L3（多步编排 + 人工审批）**；**L4 自主长链在核心业务无可信公开成功证据**。
3. **【事实】**开源话语权已从"编排台"转向"运行时"：Dify 16.0 万星、n8n 21.0 万、Langflow 15.6 万已成红海；Java 线 Spring AI Alibaba 1.11 万、LangChain4j 1.34 万、AgentScope Java 0.63 万——**"Java + 国产模型 + 私有化"有需求、无霸主**。
4. **【事实】**合规给私有化送红利：《生成式AI服务管理暂行办法》第二条把"企业自用、不向公众提供服务"排除在适用范围外；做对外 SaaS 即触发第十七条安全评估+算法备案。**"卖授权"与"卖云服务"是两套商业模型。**
5. **【推断】**空位不在"再造 Dify"，而在**"懂业务权限的后台操作 Agent 中间件"**：把每次工具调用绑定到 RBAC/数据权限、审批流、审计与可回滚事务。编排台没有业务语义，ERP 原厂又不外售平台。

## 2. 「对话即操作」的真实成熟度

| 级别 | 定义 | 国内现状 | 主要风险 |
|---|---|---|---|
| **L1** 问答/检索 | RAG 答问、查单据、给口径 | **已规模化**，近乎标配 | 幻觉引用、权限穿透 |
| **L2** 单步写 | 自然语言→1 个写 API，执行前预览确认 | **主流交付水平** | 参数幻觉（金额/科目/数量）、无幂等、无回滚 |
| **L3** 多步编排 | 跨 2~5 系统，含 planning 与人工审批节点 | **少数 demo/通稿**，量产少 | 中间态失败、长事务、审计断链 |
| **L4** 自主执行 | computer use/RPA 兜底、长链自纠错 | **不可用于核心业务** | 不可解释、不可回滚、责任无法界定 |

**依据**：用友、金蝶、泛微的叙述都停在"智能体调用企业 API 完成填报/审批"，即 **L2~L3 之间**；钉钉官方示例"帮我明天请个假→预览→提交"是标准 L2 范式：**生成 + 结构化预览 + 人工确认**（[钉钉 AI 助理](https://page.dingtalk.com/wow/dingtalk/default/dingtalk/AIzhuli)）。

**五个硬约束**

| 约束 | 表现 | 解法（判断） |
|---|---|---|
| **权限** | 以"用户身份"还是"服务身份"执行？前者继承数据权限但难跨部门自动化，后者等于超级账号 | **双身份**（用户+受限代理）；**行级/字段级数据权限**（RuoYi 系 `@DataScope`）是编排台的知识盲区 |
| **幻觉** | L2 以上代价从"答错"升级为"写错"，金额/税率/科目/库存零容错 | 靠**强类型 DTO + 后端业务校验**，模型只负责"选工具+填参数" |
| **审计** | 等保三级要求审计不可篡改，需记录触发者、输入、步骤、每次接口调用与结果 | 独立审计表 + tool call 全链路留痕 |
| **延迟** | L2 约 2~6s、L3 约 10~30s，用户习惯是 300ms | 流式输出 + 进度可视化 + 长任务后台化 |
| **成本** | Copilot Studio 容量"按月强制、不结转、超额停服"——**是可用性问题不是账单问题** | 额度池 + 小模型路由 + 缓存；这解释了国内厂商转向"年度授权+额度池" |

**反面证据**

- **【事实】**海外已现叙事回调：CB Insights 指出"早期收入胜利能否转化为可持续市场地位"待验证，壁垒归结为专有数据、垂直深度与深度集成带来的转换成本（[199IT](https://www.199it.com/archives/1776507.html)）。
- **【事实·未一手核实，仅提示，不作论证】**MIT NANDA"95% 企业 GenAI 试点无可测损益影响"（2025-08）；Klarna 在 AI 客服上线后重新招聘人工（2025）。
- **【事实】**中国使用强度的诚实刻度：2026-07 AI 办公 Agent **PC 客户端同比 +340.6%**，WorkBuddy 月活 658.2 万、QClaw 225.9 万、TRAE Work 190.4 万，但**月人均仅 19 次**（第一），其余低于 10 次（[QuestMobile via 199IT，2026-09-06](https://www.199it.com/archives/1849967.html)）。**【推断】**19 次/月≈每天不到 1 次，Agent 仍"偶尔用一下"，未成工作流主干。

**核心空白**：**没有开源项目把"后台的 RBAC/数据权限/工作流/审计"与"Agent 编排"原生打通**。Dify/n8n 是外部编排台，调用 API 却不知"当前用户能否看这条记录"；RuoYi 类有权限模型却无 Agent 运行时。二者之间是断的。

## 4. 采购与合规约束

| 约束 | 要求 | 影响 |
|---|---|---|
| **生成式 AI 备案** | 【事实】《暂行办法》第二条：企业"研发、应用生成式 AI 技术，**未向境内公众提供**服务的**不适用**本办法"；第十七条：具舆论属性/社会动员能力的须安全评估+算法备案（[CAC 2023-07-13，2023-08-15 施行](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)） | **红利**：私有化给单一企业内部用→不触发备案。**但**对外 SaaS 即触发评估+备案，并承担内容生产者责任（第九条） |
| **内容标识** | 【事实】显式+隐式标识；导出文件须含标识；不标显式标识的导出须**留存日志≥6 个月**（[CAC 2025-03-14，2025-09-01 施行](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)） | 直接约束"AI 生成报表/公文导出"：加标识+元数据+日志留存 |
| **数据出境** | 【事实】CIIO 出境须申报评估；非 CIIO 累计 10 万人以下非敏感信息可豁免，100 万人以上须申报（[CAC 2024-03-22 施行](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)） | **推断**：央国企场景等同"必须境内或本地模型"，Joule/Agentforce/Copilot 直连在总部型客户几乎不可行 |
| **等保 2.0** | GB/T 22239-2019（2019-12-01 实施）；三级要求身份鉴别、访问控制、安全审计、入侵防范、数据完整性/保密性 | Agent 必须"可鉴别、可审计、可回溯"；建议双身份+独立审计表 |
| **信创/央国企偏好** | 要求国产 CPU/OS/DB/中间件适配与安全可靠测评；倾向"原厂+集成商"、要源码/私有化、要三级等保与同业案例 | Java 栈适配成本最低；RuoYi 系信创经验是隐形资产；单子可达百万级但周期 6~12 个月，验收看"确定性场景"而非"通用能力" |

**对 RuoYi 类商业化路径的三个推论【推断】**：①**合规前置**——审计表、双身份、导出标识、日志留存做成模块自带，是投标门票；②**卖授权不卖算力**——客户自购/自建模型，你收授权+实施费，规避 token 成本与备案责任；③**不做多租户公有云**——那会把"内部工具"变成"生成式 AI 服务提供者"，合规成本跳一个量级。

## 5. 市场规模与客单价

**【事实】全球**：企业级 Agent+Copilot 年收入 2024 年 **50 亿美元**→2025 年底近 **130 亿美元**，收入集中在编程与企业工作流（[CB Insights via 199IT](https://www.199it.com/archives/1776507.html)）。

**【事实·二手】中国**：IDC 预测到 **2030 年**中国**网络安全相关** AI Agent 应用市场达 **593.5 亿元**、五年 CAGR **106.5%**（媒体转述，未取得 IDC 原文，仅作量级参考）；办公侧 2026-07 PC 客户端同比 **+340.6%**、头部 MAU 658 万（[QuestMobile](https://www.199it.com/archives/1849967.html)）。

## 6. 结论：市场空位在哪

### 6.1 三个真实空位

**① 治理层——"懂权限的 Agent 运行时"（最强）**。Dify/n8n 不知道"张三能不能看这条报销单"，RuoYi 有完整 RBAC 却没有 Agent 运行时。让 **tool 定义从后台元数据自动生成**（学金蝶"OpenAPI 契约→MCP 工具"），并让每次调用**继承当前用户数据权限+落审计+支持预览/回滚**——这件事没人做好。**这不是模型问题，是工程与治理问题，恰是 Java 后台生态的主场。**

**② 存量系统的"最后一公里"（最广）**。ruoyi-vue-pro 4.0 万星、JeecgBoot 4.8 万星，意味着数以万计自建后台：API 不规范、文档缺失、逻辑只在 Service 层。外部编排台接不进去，原厂 Agent 救不了自研系统。**"代码内嵌式（in-process）Agent"比"外挂编排台"更适配**：同进程、同事务、同权限上下文，不必为每个接口写 OpenAPI。

**③ 交付标准——"合规即产品"**。等保自查清单、审计日志 schema、导出标识、双身份、信创适配矩阵，目前每个项目重做一遍。做成开箱模块+交付方法论，成本极低、感知价值极高。

### 6.2 四条风险

1. **平台厂商向上吞并**：¥19,800/年已是"顺手买"价格。**【推断】**必须解决"跨系统、跨厂商、自研系统"，否则被"已在用的那个 App 里的助理"顺手替代。
2. **开源上游降维**：Coze Studio 以 Apache-2.0 可私有化，功能面远超单点模块。**【推断】**别在"编排能力"正面竞争，要在"业务语义与治理"上竞争。
3. **交付退化为外包**：效果依赖客户数据治理（字段规范、主数据干净）。**【推断】**无标准化场景包（请假、报销、采购申请、库存查询、经营日报）则毛利被定制吃光。
4. **写操作的责任风险**：一个错误金额就是一次事故。**【推断】**必须默认"读优先、写确认、删禁用"：L1 全自动、L2 强制预览、L3 强制审批节点、DELETE/批量更新默认不开放给模型。

### 6.3 行动建议

1. **定位**：做**"可审计的后台操作 Agent 中间件"**而非"又一个平台"；核心资产＝**Tool 生成器（元数据/OpenAPI→强类型工具）+ 权限桥 + 事务与回滚 + 审计总线**。
2. **顺序**：先 **读+报表**（L1），再 **单步写+预览确认**（L2），L3 只做"带审批节点"的受限编排。
3. **底座**：以 **AgentScope Java / Spring AI Alibaba / LangChain4j**（均 Apache-2.0）为运行时，避免 GPL-3.0 组件（如 MaxKB）进入闭源分发链。
4. **商业**：开源内核+商业版（多租户、审计增强、信创适配、场景包）；锚定"组织年度授权"，参考钉钉两档，做 **3~5 万（中小）/15~30 万（中大型私有化）**，避免按 token 计费。
5. **信任**：公开"50 个真实后台操作的成功率（含失败案例）"评测——人人宣称 Agent 的时代，**可信的失败率数据本身就是稀缺品**。
