# 平台共享词汇

本文件只收录本项目特有、容易混用的术语；通用编程概念不在此列。

## Terminology

| Term | Definition | Avoid |
| --- | --- | --- |
| ActionId | 平台允许的固定动作枚举，共 7 个；模型只能引用白名单动作，不能拼 shell。 | 工具名、命令名 |
| 配方 | 仓库内定义动作 argv 的文件，优先级为 `ci/actions.yml` → `Taskfile.yml` → `Makefile` → 内置默认。 | 脚本、插件 |
| 环境模板 | 定义一组环境变量、资源与端口租约的模板，实例化后成为项目环境。 | 环境配置、env 文件 |
| 变更确认 | 生产写操作或 L3 动作的一次性人工确认，令牌绑定 `planHash`，有效期 5 分钟。 | 审批流、二次确认 |
| 运行账本 | 记录一次运行及其阶段、产物、确认与结果的持久化账本。 | 日志、历史 |
| 文档树 | `docs/` 下由 doc-marshal 管理的类型化文档集合；`README.md` 不属于文档树。 | Wiki、知识库 |

## Relationships

- 一个 ActionId 由一条配方提供 argv，由执行器在环境或部署目标上运行。
- 一次变更确认对应一个运行账本中的变更计划。
- 环境模板实例化后产生环境变量、资源绑定与端口租约。

## Ambiguities

- “部署”既指流水线 stage，也指部署目标动作；正文必须写明是 stage 还是 `stack_deploy`。
- “审批”在旧文档中同时指权限检查和人工确认；现统一用“变更确认”。
