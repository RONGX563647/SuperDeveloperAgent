# ADR-0006：工作区事件驱动优先，轮询只做降级

- **状态**：通过
- **日期**：2026-11-13
- **关联**：[Code Wiki §5.17](../Code-Wiki.md)、`web/src/composables/useWorkspaceEvents.ts`

## 背景与痛点

工作区首页需要同时展示会话、任务、运行三份数据。原先靠定时轮询（3 秒）刷新：多标签页开着时后端压力随标签数线性增长，且状态变化有明显延迟。

## 问题陈述

继续加轮询频率，还是改成服务端推送？

## 候选方案

| 方案 | 收益 | 风险 / 成本 |
|---|---|---|
| A. 提高轮询频率 | 改动最小 | 请求量与延迟此消彼长；空闲也在打库 |
| B. WebSocket | 双向、生态成熟 | 需要额外的连接/心跳/鉴权层；当前只需服务端单向推送 |
| C. SSE + 断线降级轮询 | 复用 HTTP 鉴权；浏览器原生重连语义可控；实现小于 WebSocket | 需要处理慢消费者与断线重连 |

## 决策

选 **C**：

- 服务端 `GET /workspaces/{projectId}/events` 推送聚合事件；总线用 `directBestEffort`，**慢客户端丢弃而非无界缓冲**（真相在 SQLite，事件只是提示）；
- 前端 `useWorkspaceEvents` 用 fetch 流解析，1s→15s 指数退避重连，卸载即断开；事件就地更新，终态 1.2s 防抖对账；
- **只有事件流断开时**才启用 10 秒兜底轮询；页面不可见时不拉取。

## 影响范围

- 代码：`WorkspaceEventController`、`WorkspaceEventBus`、`useWorkspaceEvents.ts`、`WorkspaceHomeView`;
- 文档：Code Wiki §5.17；
- 运维：SSE 需要网关/反代放行长连接并关闭响应缓冲（见[运维手册](../operation/README.md)）。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 代理缓冲导致事件不实时 | 运维手册明确 `X-Accel-Buffering: no`、禁用 gzip 缓冲 |
| 事件丢失导致界面陈旧 | 终态对账 + 断线轮询；事件不承担强一致职责 |
| 长连接占满线程 | Tomcat 虚拟线程；单项目订阅数受浏览器标签数约束 |

## 后果

空闲时零轮询、状态变化近实时；代价是引入长连接与降级逻辑，需在运维层保证代理配置正确。
