# 设置：服务器配置 + 模型连接 · 实现说明 v1

> 日期：2026-11-09 ｜ 状态：已实现并验证
> 入口：侧栏「设置」（`/settings`）｜ 权限：读 `settings:read`（ADMIN/DEVOPS），写 `settings:write`（ADMIN）

---

## 1. 为什么需要它

- **服务器配置**原本只在 `application.yml`（`agent.deploy.server.*`），改一次要重启，且只能配一台；
- **模型连接**原本同样靠环境变量，启动期建单例，换模型 = 重启；
- 参考 `ruoyi-ai` 的 `chat_provider` / `chat_model` 管理思路，但修正两点：**API Key 加密落库**（参考实现是明文）、**提供连通性测试**（参考实现没有）。

## 2. 数据模型（SQLite `_platform/projects.db`）

```sql
deploy_servers   -- id/name/host/port/ssh_user/auth_type/key_path/
                 -- secret_enc/secret_iv/remote_dir/enabled/is_default/
                 -- last_test_at/last_test_ok/last_test_msg/updated_by/updated_at

model_connections -- id/name/provider/base_url/api_key_enc/api_key_iv/
                  -- model_name/temperature/max_iters/enabled/is_default/
                  -- last_test_* / updated_by/updated_at
```

- 密钥字段 **AES-256-GCM** 加密（`SecretBox`，主密钥 `AGENT_SECURITY_MASTER_KEY` 或本地 `platform.key`）；
- 接口只返回 `hasSecret` + 掩码 `****`，**永不回显明文**；
- 同表 `is_default` 唯一：保存时在事务内把其它行清零；
- 表结构用 `CREATE TABLE IF NOT EXISTS` 初始化（与现有 SQLite 存储一致，不引入 Flyway）。

## 3. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/settings/servers` | 列表（密码掩码） |
| POST/PUT/DELETE | `/api/v1/settings/servers[/{id}]` | 增改删；`secret` 留空 = 不修改 |
| POST | `/api/v1/settings/servers/{id}/default` | 设默认（流水线「远程服务器」用它） |
| POST | `/api/v1/settings/servers/{id}/test` | 测试已保存配置 |
| POST | `/api/v1/settings/servers/test` | **未保存也可测**（保存前验证） |
| GET | `/api/v1/settings/models` | 列表（Key 掩码） |
| POST/PUT/DELETE | `/api/v1/settings/models[/{id}]` | 增改删；`apiKey` 留空 = 不修改 |
| POST | `/api/v1/settings/models/{id}/default` | 设默认（运行时立即生效） |
| POST | `/api/v1/settings/models/{id}/test` | 测试已保存配置 |
| POST | `/api/v1/settings/models/test` | **未保存也可测** |
| GET | `/api/v1/settings/models/options` | 轻量：当前默认模型名（对话页徽标用） |

测试连接返回：`{ok, latencyMs, message, dockerVersion?|reply?}`。

- 服务器测试：**纯 Java SSH（JSch）**，密码/密钥都可非交互执行；首次连接把主机指纹写入
  `<workspace>/_platform/known_hosts`，之后指纹变化直接拒绝（防中间人）；
  错误分类提示：认证失败 / 连接超时 / 端口拒绝 / docker 不可用；
- 模型测试：POST `{baseUrl}/chat/completions`（`max_tokens=1`、15s 超时），错误信息做密钥脱敏。

## 4. 运行时行为

### 4.1 模型热切换

`DynamicModelProvider` 按「id + baseUrl + model + apiKey 哈希 + temperature」做指纹：

- 配置不变 → 复用同一个 `Model` 实例（连接池不重建）；
- 设置页保存/设默认 → 指纹变化 → 下一次对话自动重建；
- 库为空 → 回退 `agent.model.*`（环境变量），行为与改造前一致。

### 4.2 部署服务器

`ServerDeployer` 改为从配置库解析服务器：

- 选择顺序：`pipeline.yml` 的 `deploy.serverId` → 默认服务器（enabled 优先）→ 无则 E-505；
- 无配置时错误文案直接指引「设置 → 服务器」；
- `GET /api/v1/ci/deploy/targets` 的 `server.available` 现在由配置库决定，并显示默认服务器名。

## 5. 前端

```
云端工作台（/settings）                           [刷新]
管理服务器与模型连接
┌ 左侧分区导航 ┐   ┌ 右侧内容卡片（无浮层） ─────────────┐
│ >_ 服务器     │   │ 分区标题                    + 添加   │
│    连接与运行环境│   │ 内联表单（添加/编辑时展开，不弹窗）   │
│ ⚙ 模型连接    │   │ 列表：状态 / 默认 / 操作             │
│    推理服务与密钥│   │                                     │
│ ⑃ 代码仓库    │   │                                     │
│    授权与连接  │   │                                     │
└───────────────┘   └─────────────────────────────────────┘
```

- **服务器**：列表 + 内联表单（名称/主机/端口/用户/认证方式/私钥或密码/远端目录）
  + [测试连接]（未保存也能测）+ [连接并保存]；不弹浮层，与列表同屏；
- **模型连接**：厂商预设自动填 BaseURL；BaseURL/模型名/API Key/温度/迭代；
  测试连接显示延迟与模型回复首句；
- **代码仓库**：从「接入项目」页迁移过来的 Gitee 授权（OAuth / 私人令牌 / 解绑），
  绑定后可预览最近 6 个仓库；接入页只保留状态提示与「去设置授权」跳转；
- 切换分区自动重新拉取数据；窄屏左导航折叠为横向卡片。

联动：

- 对话页底部徽标显示设置页的默认模型（未配置时显示占位）；
- 流水线部署目标「远程服务器」在配置后变为可用，提示文案显示默认服务器。

## 7. 与 `application.yml` 的关系

| 场景 | 行为 |
|---|---|
| 设置页为空 | 使用 `agent.model.*` / `agent.deploy.server.*`（完全兼容旧行为） |
| 设置页有配置 | **以设置页为准**；yml 仅作兜底 |
| 删除全部模型连接 | 回退到 env 模型 |
