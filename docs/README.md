## 2. 目录规范与迁移状态

目标结构（新文档一律按此落位）：

```
docs/
├── README.md            本索引（唯一入口）
├── adr/                 架构决策记录（ADR-000x）
├── architecture/        架构图、数据流、模块边界
├── api/                 接口索引（以控制器为准，不引 springdoc）
├── operation/           部署、排障、备份、回滚
├── dev/                 本地启动、调试、质量门禁
├── changelog/           按月的变更记录
├── deprecated/          废弃登记（含删除原因与替代物）
└── *.md                 存量设计/规约/决策文档（保持原位，暂不搬动）
```

**迁移策略**：存量 24 篇仍留在 `docs/` 根目录，避免一次性移动导致全仓链接失效；新文档写入对应子目录。目录里出现的「存量」条目即待迁移项，迁移时须同步本索引、根 README、Code Wiki 三处链接。

## 4. 问题分级与处置（禁止无验证删除）

| 级别 | 判定 | 默认动作 |
|---|---|---|
| **P0** | 构建失败、关键链路文档缺失、死链 | 立即修；无法当轮修则建 Gitee Issue（标签 `wikidoc`/`文档治理`/`P0`） |
| **P1** | 内容与代码不一致、过期、辅助文档缺失 | 出修复草案，**人工确认后**再并入 |
| **P2** | 文风、冗余、排版 | 记录进健康报告，攒批处理 |

红线：

1. 删除正式文档前必须在本索引与 [废弃登记](deprecated/README.md) 留痕，并给出替代物；
2. 同一事实只写一处，其余用链接引用，禁止复制粘贴；
3. 代码仓库与外部 Wiki 只做「索引同步」，**不做双向覆盖**；发现循环同步风险立即暂停并告警；
4. 长耗时文档重写不得放在回调/请求阻塞链路里执行；
5. 无法确认的信息输出风险清单，不编造。

## 5. 巡检与校验

```bash
# 1) 文档链接（本仓脚本，退出码非 0 即有断链）
node scripts/docs/check-links.mjs

# 2) 代码侧约束与单测（同时校验文档引用的模块/路由是否还存在）
mvn -q -f platform/pom.xml verify

# 3) 前端类型与构建
cd platform/web && npm run typecheck && npm run build
```

巡检项：断链、过期复审日、代码-文档一致性（本轮人工比对：路由 / 工具数 / 配置键 / 模块数）、ADI 缺失（架构变更是否补 ADR）、重复段落、孤立文档（未被本索引引用）。
