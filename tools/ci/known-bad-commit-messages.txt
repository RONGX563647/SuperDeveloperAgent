# 历史遗留的坏提交白名单（提交信息里中文已不可逆地变成问号）
#
# 为什么需要：这些提交已经在 origin/main 与 origin/0.1.0-snapshot 上，
# 每次「snapshot → main」同步 PR 都会把它们重新带进 base..head 范围，
# 没有白名单的话新 PR 会因为陈年旧账永远红。清理历史（改写 + force-push）
# 之前，先在这里登记，新提交照旧拦截。
#
# 格式：一行一个 sha 前缀（7~40 位），# 之后是注释。删除某一行 = 该提交重新纳入检查。
#
# ── 2026-11-19：白名单已清空 ───────────────────────────────────────────────
#
# 这里原本逐条登记了 10 条坏提交。核对后发现它们 100% 是「平台合并 PR 时
# 生成」的提交：subject 以 `(PR #n)` 结尾，中文在平台侧就被替换成问号，
# 与我们本地的编码习惯无关。逐条维护白名单等于给同一个系统性问题打 10 次补丁，
# 因此改为在门禁里自动识别（见 check-commit-messages.py 的 PLATFORM_MERGE_SUBJECT）：
#   - 平台合并提交：识别后只提示「中文已被替换」，不阻断；
#   - 其它损坏提交：照旧阻断，不给任何豁免。
#
# 实测这 10 条全部被自动识别覆盖，所以白名单不再需要条目。
# 保留文件（而非删除）是为了：将来真需要豁免时仍有统一入口，修改痕迹也可追溯。
